# BeaconGalaxy

Firmware for the Galaxy board (STM32F405RG). It drives:

- a 22×22 WS2812 LED matrix;
- a 64×48 OLED menu, built with TouchGFX;
- four buttons and four status LEDs;
- a microSD card and an EEPROM.

It plays GIF animations and themes on the matrix and shows an audio
equalizer. It also controls the audio player board over a serial link.

Part of a three-repository system:

| Repository | What it is |
|---|---|
| **BeaconGalaxy** (this one) | the application, at 0x08040000 |
| [GalaxyBoot](https://github.com/ElectronicsBuilder/GalaxyBoot) | its bootloader: updates BeaconGalaxy from the SD card |
| [AudioGalaxy](https://github.com/ElectronicsBuilder/AudioGalaxy) | the audio player (STM32F407G-DISC1) controlled over the link |

## Features

- **Menu (OLED, TouchGFX 4.27):** themes, GIFs, equalizer, colours, audio
  (playlist, record, volume, repeat, pause/stop), settings, and About with the
  SD-card upgrade.
- **Autoplay from the start screen:** UP plays tracks, BACK plays GIFs, DOWN
  plays themes.
- **GIFs:** `<NAME>-<n>.bmp` frames from the SD card, 24- or 32-bit, scaled to
  22×22. A frame index makes each frame load in about 7 ms, even with
  thousands of files in the root folder.
- **Themes:** Fire, Meteor, Bouncing, Plasma, Stars, Rain, Swirl, Life.
- **Equalizer:** 22 bands from the microphone (FFT), shown as bars or a VU
  meter.
- **Status LEDs:** 10 dimmable effects (PWM). With the DMA indicator on, the
  blue LED shows matrix transfers.
- **SD card:** removal and insertion are noticed without a detect switch, and
  the start screen shows NO SD.
- **Settings:** stored in the EEPROM with a CRC.
- **Watchdog:** the App, GUI and fx tasks are supervised; a stuck task resets
  the board, and the next boot reports which task it was.

## Build

You need STM32CubeCLT 1.16 (arm-none-eabi-gcc, CMake, Ninja) on the PATH, and
Python 3, which writes the update file.

```
cmake --preset Release
cmake --build --preset Release
```

`Release` (`-Os`) is the build to run on the board; `Debug` (`-O0 -g3`) is for
the debugger. The build writes:

- `build/<preset>/BeaconGalaxy.elf`, for flashing over SWD;
- `build/<preset>/BeaconGalaxy.bin`, the SD-card update file (application
  plus a CRC trailer).

VS Code tasks (`.vscode/tasks.json`) cover building, flashing, the console
over SWD, TouchGFX generation, the host tests and the CI checks.

## Flash

The application lives at 0x08040000; GalaxyBoot occupies the first 256 KB.

```
STM32_Programmer_CLI -c port=SWD sn=<st-link serial> mode=UR -w build/Release/BeaconGalaxy.elf -v -rst
```

To update without a probe:

1. Copy `BeaconGalaxy.bin` to the root of the SD card.
2. Choose **About › UPGRADE**, or hold ENTER while resetting.

## Console

- **Serial:** USART1 through the on-board FT232, 115200 baud.
- **Over SWD, no wiring:**
  `python tools/swd_console.py build/Release/BeaconGalaxy.elf <st-link serial> "help"`

Useful commands:

| Command | What it does |
|---|---|
| `fx` | matrix effects (`fx gif BAT`, `fx theme fire`, `fx eq vu`, `fx test 1`) |
| `sd` | SD card (`ls`, `info`, `mv`, `rm`) |
| `link` | link to the audio board |
| `key` | presses a front button |
| `wdg` | watchdog: supervised tasks, last reset cause, tests (`wdg stall fx`, `wdg hang`) |
| `tasks`, `ee`, `led`, `oled` | RTOS tasks, EEPROM, status LEDs, OLED tests |

## Layout

| Folder | Contents |
|---|---|
| `App/` | our code: main loop, matrix and effects, GIF player, equalizer, SD card, EEPROM settings, link, UI bridge, console |
| `TouchGFX/` | the TouchGFX project (`BeaconGalaxy.touchgfx`); screens in `gui/`, the custom HAL in `target/` |
| `common/` | code shared with GalaxyBoot and AudioGalaxy (console, CRC, protocol, OLED and EEPROM drivers) |
| `Core/`, `Drivers/`, `Middlewares/`, `FATFS/` | generated by STM32CubeMX 6.15. Edit `BeaconGalaxy.ioc` (changes are recorded in `cubemx/beacongalaxy.patch`), then run `sh tools/cubemx_generate.sh .` |
| `tests/host/` | PC unit tests: `sh tests/host/run_tests.sh` |
| `docs/` | [overview](docs/port-writeup.md), [protocol](docs/protocol.md), [memory map](docs/memory-map.md) |
